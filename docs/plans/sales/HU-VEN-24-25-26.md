## API
`apps/api/src/modules/sales/cash/` — new `CashShiftReviewService`, `CashShiftHistoryService`; routes added to `CashController`:
| Method · route | Permission | Error `code`s |
|---|---|---|
| `GET /sales/cash-shifts` (`from`, `to`, `cashierId`, `registerId`, `status`, `page`, `pageSize`) | any of `sales.cash-register.open`, `sales.cash-register.review` (own shifts only without review) | `INVALID_FILTER` |
| `GET /sales/cash-shifts/:id/review` | review, or the shift's cashier (read-only) | `CASH_SHIFT_NOT_FOUND`, `CASH_SHIFT_NOT_OWNED` |
| `POST /sales/cash-shifts/:id/approve` `{ comment? }` | `sales.cash-register.review` | `VALIDATION_FAILED`, `CASH_SHIFT_NOT_FOUND`, `CASH_SHIFT_NOT_CLOSED`, `CASH_SHIFT_SELF_REVIEW` |
| `POST /sales/cash-shifts/:id/observe` `{ comment }` | `sales.cash-register.review` | same + `REVIEW_COMMENT_REQUIRED` |

- Decide tx (`prisma.tenant.$transaction`): `lockShiftForUpdate` (existing, `cash-ledger.ts`) → status `CLOSED` → reviewer ≠ `openedById` → `cashShiftMachine.next` → update `status`, `reviewedById`, `reviewedAt`, `reviewNote` → pending `ApprovalRequest CASH_DIFFERENCE` `FOR UPDATE` through `approvalRequestMachine` (`decidedBy/At`, `comment`) → `AuditService.log` `sales.cash-shift.approve|observe` → `OutboxService.publish('sales.cash-shift.reviewed', …, { tx, idempotencyKey: 'cash-shift-reviewed:<id>' })`.
- Review read: shift + `cash_shift_method_totals` + `cash_counts` + the request + `audit_logs` of the shift (timeline) + user names; sales total from `loadShiftSales`.
- List: one grouped query for sales count/total per shift (no N+1); totals and month KPIs with aggregate queries over the same scope.
- `cash-shifts.service.ts` `open`: assign `number` with `nextDocumentNumber` inside the opening tx; mappers expose it.

`apps/api/src/modules/sales/pricing/` — new `PricesController`, `PricesService`, `prices.dto.ts`, `prices.errors.ts`, `price-change.recorder.ts`:
| Method · route | Permission | Error `code`s |
|---|---|---|
| `GET /sales/prices` (`q`, `brandId`, `categoryId`, `priced=with|without`, `branchId`, `page`, `pageSize`) | `sales.prices.edit` | `INVALID_FILTER` |
| `GET /sales/prices/:productId` (current price, last changes; cost and margin only with `inventory.costs.view`) | `sales.prices.edit` | `PRODUCT_NOT_FOUND` |
| `PATCH /sales/prices/:productId` `{ newPrice, expectedPrice, reason? }` | `sales.prices.edit` | `VALIDATION_FAILED`, `PRODUCT_NOT_FOUND`, `INVALID_PRICE`, `PRICE_UNCHANGED`, `PRICE_CHANGED` |

- Edit tx: `SELECT … FROM products … FOR UPDATE` → compare `expectedPrice` → `validatePriceEdit` → update `sale_price`, `updated_by_id` → `recordPriceChange(tx, { productId, oldPrice, newPrice, source, reason })` → audit `sales.price.update` → outbox `sales.price.changed`.
- `recordPriceChange` is also called from `inventory/product-commands.service.ts` (update, `PRODUCT_FORM`) and `inventory/product-import.service.ts` (`IMPORT`) when the stored price differs; product creation writes none.
- KPIs: products with price / total, without price (`sale_price = 0`), changes this month (La Paz), average margin only with `inventory.costs.view` (otherwise omitted, never sent).
- New outbox types `sales.cash-shift.reviewed`, `sales.price.changed` in `outbox.service.ts`, routed in `apps/worker/src/common/queues.ts` (accounting / no consumer yet).

## Risks and doubts
1. **Self-review blocked:** a user cannot approve or observe their own shift (`CASH_SHIFT_SELF_REVIEW`). A one-person shop needs a second user with the review permission.
2. `OBSERVED` is final: the cashier sees Accounting's comment but cannot recount in the system; any correction is handled outside (decision above).
3. "Aprobado con descuento al cajero según política (PENDIENTE)" in Figma: no payroll discount is modelled; the answer is free text.
4. No approvals inbox yet (HU-VEN-29): reviewers reach pending closings from the history ("Por revisar" KPI and filter).
5. Shifts closed before this branch get their `T-` number by backfill, ordered by opening time.
6. Editing a price bumps `products.updated_at`, so an inventory editor with the product form open gets the existing stale-edit conflict; intended.
7. "Sin precio" means `sale_price = 0` (the column is not nullable). A price of 0 cannot be set from the Precios screen.
8. Price changes made before this branch have no history; "Última actualización" shows "—" for them.
9. Block E of the backlog pairs 26 with 27 and puts 35 (rounding) first: the single edit applies no rounding; HU-VEN-27 reuses `recordPriceChange` with `BULK` + `batchId`.
10. VP-11 texts mentioning rules, approvals and export are dropped; confirm the shortened subtitle with design.
